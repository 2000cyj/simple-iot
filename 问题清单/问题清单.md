## 一、Critical（8）

### C-01 · 初始化脚本 admin 密码为 `admin` 且不强制改密
- **文件**：`doc/sql/init.sql:656`
- **类别**：security
- **验证**：已验证（本地 bcryptjs 比对：工作区当前 hash `$2a$10$51hB9kf...LQtm` 对应明文 `admin`）
- **问题**：init.sql 写入的 admin 密码 hash 校验结果为 `admin`，且该行 `force_change_pwd='f'`。注意**当前工作区未提交的改动**把 hash 从 `Admin@2026`（`$2a$10$6g2lLkAo...`，见 `doc/sql/migrations/20260722_001_auth_hardening.sql:6`）改回了 `admin` 并把强制改密置为 `f` —— 相对 HEAD 是安全回退。迁移脚本 `20260722_001_auth_hardening.sql` 只作用于存量库，新装库走 init.sql 路径完全没有强改密保护。
- **影响**：任何按默认部署的实例，admin 账号口令公开在 Git 历史里且无需改密即可进入系统。
- **建议**：init.sql 恢复为 `Admin@2026` 的 hash 且 `force_change_pwd='t'`；首次登录校验 `forceChangePwd` 并强制跳转改密页（当前服务端只把该值作为返回字段，见 H-14）。

### C-02 · `/webhook/**` 免登录白名单把管理接口一起放行
- **文件**：`iot-server/src/main/resources/application.yml:64-67`、`iot-server/src/main/java/com/github/dingdaoyi/config/satoken/SaTokenConfigure.java:53-61`、`iot-server/src/main/java/com/github/dingdaoyi/controller/iot/WebhookIngressController.java:24`
- **类别**：security
- **验证**：已验证（`skip-url` 含 `/webhook/**`；`SaTokenConfigure` 用同一份 skipUrl 排除 Sa 拦截器；`WebhookIngressController` 的 `@RequestMapping("/webhook/config")` 落在该通配下；`WebhookReceiverController` 才是真正的接收端 `@RequestMapping("/webhook")` + `@PostMapping("/{token}")`）
- **问题**：`GET/POST/PUT/DELETE /webhook/config`、`POST /webhook/config/{id}/regenerate-secret` 全部免登录。`create` 返回体含明文 `token` + `secret`，且 `deviceId` 由请求方指定。
- **影响**：未认证攻击者可创建指向任意设备的接入点 → 拿到 token/secret → 向 `/webhook/{token}` 发送合法 HMAC 报文，**伪造任意设备的遥测与事件上报**；`regenerateSecret` 还能把存量配置的密钥作废造成拒绝服务。
- **建议**：免登名单收窄为精确路径 `/webhook/{token}`；管理接口迁到 `/webhook-config/**` 或单独鉴权；接入配置绑定到登录用户/租户；secret 仅创建时返回一次，之后一律脱敏。

### C-03 · 协议类型 JAVA 支持从任意本地路径加载 JAR 并反射实例化 → RCE
- **文件**：`iot-server/src/main/java/com/github/dingdaoyi/iot/proto/impl/JavaProtocolInitialize.java:64-135`（`createProtocolDecoder` / `loadFromJar`）、`iot-server/src/main/java/com/github/dingdaoyi/controller/iot/ProtocolController.java:40-43`（`save`）、`:60-63`（`setStatus`）、`iot-server/src/main/java/com/github/dingdaoyi/service/impl/ProtocolServiceImpl.java:61-80`
- **类别**：security
- **验证**：已验证（`loadFromJar` 用 `new File(jarUrl).toURI().toURL()` + `URLClassLoader` 加载并 `setAccessible(true)` 调构造器；`Protocol` 实体的 `url` / `handlerClass` 由 `POST /protocol` 的 `@RequestBody Protocol protocol` 直接带入，无 `@Valid`、无路径白名单；`PUT /protocol/{id}/status?enable=true` 触发 `ProtocolFactory.reloadProtocol`）
- **影响**：登录用户提交 `protoType=1`（JAVA）、`url=/tmp/evil.jar`、`handlerClass=Evil` 并启用协议，即可**加载任意 JAR、实例化任意类**。
- **建议**：`ProtoType.JAVA` 不允许通过 HTTP 接口创建/启用；JAR 仅从受控目录加载（白名单前缀 + 签名校验）；`handlerClass` 白名单化。

### C-04 · 脚本协议支持从任意本地路径读文件并当作脚本执行
- **文件**：`iot-server/src/main/java/com/github/dingdaoyi/iot/proto/impl/ScriptProtocolInitialize.java:105-135`（`createFromFile`）
- **类别**：security
- **验证**：已验证（`Paths.get(scriptPath)` + `Files.readString`，`scriptPath` 来自 `protocol.getUrl()`，与 C-03 同一入口可控）
- **影响**：任意文件读取 + 脚本内容注入。
- **建议**：删除基于本地路径的协议加载分支，或限定在固定脚本目录内并做 `normalize()` + 前缀校验。

### C-05 · 文件下载存在目录穿越，可读取服务器任意文件
- **文件**：`iot-server/src/main/java/com/github/dingdaoyi/controller/system/FileController.java:53-80`（`download`）、`iot-server/src/main/java/com/github/dingdaoyi/service/impl/LocalStorageService.java:55-75`（`getFileMetadata`）
- **类别**：security
- **验证**：已验证（`request.getRequestURI()` → `substringAfter(path,"file")` → `URLDecoder.decode` → `Paths.get(localDir, path)`，全程无 `normalize()`、无前缀校验）
- **影响**：`GET /iot/file/..%2f..%2f..%2fetc/passwd` 可穿越出 `./file/upload`。
- **建议**：`Path resolved = localDir.resolve(path).normalize()`，校验 `resolved.startsWith(localDir)` 否则 400；拒绝含 `..` 的路径。

### C-06 · 文件上传文件名未清洗 → 目录穿越写 / 覆盖文件
- **文件**：`iot-server/src/main/java/com/github/dingdaoyi/service/impl/LocalStorageService.java:40-52`（`uploadFile`）、`iot-server/src/main/java/com/github/dingdaoyi/service/impl/S3StorageService.java:66-80`
- **类别**：security
- **验证**：已验证（`RandomStringUtils.secure().nextNumeric(10) + "_" + file.getOriginalFilename()`，`getOriginalFilename()` 完全由客户端控制）
- **影响**：文件名含 `../` 或绝对路径时，文件写到 `localDir` 之外，或覆盖既有文件。
- **建议**：只取 `Paths.get(originalFilename).getFileName()`，再做字符白名单 `[A-Za-z0-9._-]`，并用 `Files.createFile` 避免覆盖。

### C-07 · 设备密钥 / 推送签名密钥 / 短信密钥明文下发给任意登录用户
- **文件**：
  - `iot-server/src/main/java/com/github/dingdaoyi/controller/iot/DeviceController.java:71-75`（`list` 返回 `List<Device>` 原始实体）、`:36-40`（`details` 返回 `DeviceVo`）、`:78-84`（`page` 返回 `DevicePageVo`）、`iot-server/src/main/java/com/github/dingdaoyi/model/vo/DeviceVo.java:22`（`extends Device`）、`iot-server/src/main/java/com/github/dingdaoyi/model/vo/DevicePageVo.java:12`（`extends Device`）
  - `iot-server/src/main/java/com/github/dingdaoyi/controller/iot/PushConfigController.java:74-80`（`list` 返回 `List<PushConfig>`）、`iot-server/src/main/java/com/github/dingdaoyi/controller/iot/PushConfigController.java:36-42`（`details` 返回 `PushConfigDetailVo`）
  - `iot-server/src/main/java/com/github/dingdaoyi/controller/system/SmsController.java:36-43`（`listConfig` 返回 `SmsConfig`）
  - `iot-server/src/main/java/com/github/dingdaoyi/controller/iot/ImPushConfigController.java:25-29`（`list` 返回 `ImPushConfig`）
- **类别**：security
- **验证**：已验证（`Device.deviceSecret`、`PushConfig.httpSignSecret`、`PushConfig.mqttPassword`、`SmsConfig.accessKey/secretKey`、`ImPushConfig.secret` 均为实体字段，且对应 VO 继承实体，Mapper 的 `dvs_column_list` 直接 select `device_secret`）
- **影响**：任何登录用户可批量导出全部设备 MQTT 密钥、推送 HMAC 签名密钥、短信云 AK/SK、IM 推送签名 secret。
- **建议**：密钥只在创建时返回一次；列表/详情统一脱敏（`****` 或布尔「已配置」）；设备导出 Excel 的 `dvs_column_list` 同样排除 `device_secret`。

### C-08 · 前端镜像构建必失败：Dockerfile 未 COPY `pnpm-workspace.yaml`
- **文件**：`iot-web/Dockerfile:7,10-11`
- **类别**：bug / build

## 二、High（27）

### 认证 / 授权

- **H-01 · 限流 key 取自客户端可伪造的 `X-Forwarded-For`**
  `iot-server/src/main/java/com/github/dingdaoyi/config/RateLimitInterceptor.java:36-52` · security · **已验证**
  未取首段、无可信代理判定，攻击者每次伪造不同 IP 即可无限绕过 120/min 限制。
  **建议**：仅在可信反代场景采信 `X-Forwarded-For`（配置可信代理 CIDR），否则用 `getRemoteAddr()`。

- **H-02 · 登录接口同时被排除在限流之外，且无失败锁定**
  `iot-server/src/main/resources/application.yml:64-67` + `SaTokenConfigure.java:57-61` + `iot-server/src/main/java/com/github/dingdaoyi/controller/system/UserController.java:40-59` · security · **已验证**
  `skip-url` 一份列表同时喂给 Sa 拦截器和限流拦截器 → `/user/login` 无任何频率约束；`doLogin` 无失败计数、无锁定、无验证码。
  **建议**：鉴权跳过名单与限流跳过名单拆成两个配置；登录按账号维度做失败计数 + 指数退避锁定（参考 `driver/mqtt/MqttServerAuthHandler.java:52-60` 的 FailTracker）。

- **H-03 · 登录失败文案区分「账号不存在」与「密码错误」→ 用户名可枚举**
  `iot-server/src/main/java/com/github/dingdaoyi/controller/system/UserController.java:52-56` · security · **已验证**
  **建议**：统一失败文案为「用户名或密码错误」。

- **H-04 · 全项目零角色/权限注解，任意登录用户可操作全部资源**
  `iot-server/src/main/java/com/github/dingdaoyi/controller/**` · security · **已验证**（`grep -rn "@SaCheckRole\|@SaCheckPermission" iot-server/src/main/java` 命中数 = 0）
  `AuthUtil.hasRole/hasPermission`（`auth/AuthUtil.java:56-66`）已定义但全仓零调用；`tb_user` 无角色/租户字段，设备/产品/告警/推送配置/OTA 任务也无 owner 字段。
  **建议**：引入角色或租户维度，给核心表加 `owner_id/tenant_id` 并在 Service 层强制过滤；高危写操作加 `@SaCheckRole`。

- **H-05 · 登录未校验 `enabled` / `accountNonExpired`**
  `iot-server/src/main/java/com/github/dingdaoyi/controller/system/UserController.java:40-50` · bug/security · **已验证**
  只校验 `accountNonLocked`，被停用账号仍可登录；`forceChangePwd` 仅作为返回字段，服务端不拦截后续请求。
  **建议**：登录时校验 `enabled`/`accountNonExpired`；`forceChangePwd=true` 时用拦截器限制除改密外的接口。

- **H-06 · 审计日志用户名恒为 `anonymous`（类型强转必抛异常）**
  `iot-server/src/main/java/com/github/dingdaoyi/config/AuditLogAspect.java:42-46` · bug · **已验证**
  `entity.setUsername((String) StpUtil.getLoginId())` —— 登录 ID 实际是 `Integer` 用户 id，强转必然 `ClassCastException`，被 `catch (Exception ignored)` 吞掉。
  **建议**：改用 `String.valueOf(StpUtil.getLoginId())` 或 `AuthUtil.getUsername()`。

- **H-07 · 审计日志在目标方法抛异常时不落库**
  `iot-server/src/main/java/com/github/dingdaoyi/config/AuditLogAspect.java:30` · bug · **待复核**
  `joinPoint.proceed()` 在前，异常路径直接抛出，失败操作无审计记录。
  **建议**：try/catch/finally 包裹，异常路径也写审计。

### 注入 / 输入校验

- **H-08 · InfluxQL 注入：`identifier` 直接拼接进查询**
  `iot-server/src/main/java/com/github/dingdaoyi/iot/influx/InfluxDataProcessor.java:216-221`（`metric`）、`:336-352`（`aggregate`） · security · **已验证**
  `identifier` 来自请求体，直接拼进 `select "<identifier>", time from ...` 和 `fn("<identifier>")`；`fn`/`interval` 有白名单而 `identifier` 没有。
  **建议**：`identifier` 强制 `^[A-Za-z_][A-Za-z0-9_]*$` 白名单校验，不通过直接拒绝。

- **H-09 · ORDER BY 注入面：排序字段无白名单**
  `iot-server/src/main/java/com/github/dingdaoyi/utils/PageHelper.java:27-44` + `iot-server/src/main/java/com/github/dingdaoyi/model/PageQuery.java:28-29` · security · **已验证**
  `sortFields` 是前端任意字符串数组，`OrderItem.setColumn` 仅做 blank 替换，MyBatis-Plus 以 `new Column(column)` 原样拼进 ORDER BY。所有分页接口（`/alarm/page`、`/device/page`、`/product/page` …）均可触发。
  **建议**：在 `PageHelper.page` 中对排序字段做实体字段白名单映射，非法值丢弃或 400。

- **H-10 · 批量赋值（mass assignment）：多个接口直接以实体对象入参落库**
  `iot-server/src/main/java/com/github/dingdaoyi/controller/iot/ProtocolController.java:40-48`、`controller/iot/DashboardController.java:96-110`、`controller/system/IconController.java:33-45`、`controller/iot/ModbusController.java:43-58`、`controller/iot/ImPushConfigController.java:31-38` · security/bug · **已验证**
  实体入参无 `@Valid`、无字段白名单，可写入 `id`、审计字段，甚至 `handlerClass`/`url`/`scriptContent`（与 C-03/C-04 组合成 RCE）。
  **建议**：改用 `*AddQuery`/`*UpdateQuery`（项目已有该模式，如 `DeviceAddQuery`），实体字段只由服务端赋值。

- **H-11 · IM 推送 webhook 未过 SSRF 守卫**
  `iot-server/src/main/java/com/github/dingdaoyi/service/push/WebhookNotificationService.java:41-72` · security · **已验证**
  钉钉/企微/飞书推送直接把 `config.getWebhookUrl()` 交给 hutool `HttpRequest.post(url)`，绕过了只用于 `HttpPushDeliveryService` 的 `PushEndpointGuard`。
  **影响**：可探测/访问内网服务与云元数据地址。
  **建议**：所有出网 webhook 统一走 `PushEndpointGuard.validate(url)`；IM 平台域名做白名单。

- **H-12 · `PushEndpointGuard` 存在 DNS rebinding 与 30x 跳转绕过**
  `iot-server/src/main/java/com/github/dingdaoyi/service/push/PushEndpointGuard.java:24-52` · security · **待复核**
  校验时解析一次域名、请求时再解析一次，存在 TOCTOU；`RestTemplate` 默认跟随跳转，公网 302 → 内网即可绕过；`isSiteLocalAddress()` 不覆盖 CGNAT `100.64.0.0/10` 与 IPv4-mapped IPv6。
  **建议**：拒绝 30x；连接级固定已校验 IP；补齐内网网段黑名单。

- **H-13 · `RestTemplate` 无超时，且配置里的 `httpTimeout` 从未被使用**
  `iot-server/src/main/java/com/github/dingdaoyi/config/base/MicaConfig.java:50-52` + `iot-server/src/main/java/com/github/dingdaoyi/service/push/HttpPushDeliveryService.java:96-104` · bug/performance · **已验证**
  `new RestTemplate()` 无 connect/read timeout；`PushConfig.getHttpTimeout()`（默认 5000）从未被应用。对端黑洞时线程永久挂起，再叠加 `Thread.sleep` 退避阻塞调用线程。
  **建议**：`SimpleClientHttpRequestFactory` 设超时，并在 `deliverHttp` 中读取 `config.getHttpTimeout()`。

### 脚本引擎

- **H-14 · 协议脚本调试接口对任意登录用户开放服务端 JS 执行，且无超时**
  `iot-server/src/main/java/com/github/dingdaoyi/iot/proto/script/ScriptProtocolDecoder.java:85-135`、`iot-server/src/main/java/com/github/dingdaoyi/controller/iot/ProtocolController.java:67-95` · security · **已验证**
  `POST /protocol/test/decode`、`/test/encode` 接受请求体中的 `scriptContent` 并 `context.eval("js", ...)`。虽 `allowAllAccess(false)` 限制宿主访问，但未设语句数/超时上限，`while(true){}` 即可永久占用线程（脚本跑在设备上行数据链路上）。
  **建议**：脚本调试仅管理员；`Context` 设置语句数上限与超时；执行放独立有界线程池并可中断。

- **H-15 · GraalVM `Context` 被多线程共享，非线程安全**
  `iot-server/src/main/java/com/github/dingdaoyi/iot/proto/script/ScriptProtocolDecoder.java:50,87` · bug · **待复核**
  每个协议只建一个 `Context`，注册进全局 `DECODERS` 后被所有设备消息线程并发 `execute`。
  **建议**：按线程 `ThreadLocal<Context>` 或对 decode 串行化。

- **H-16 · 规则链脚本节点/调试接口执行用户脚本，无超时且不限流**
  `iot-server/src/main/java/com/github/dingdaoyi/rule/node/ScriptFilterNode.java:52-70`、`iot-server/src/main/java/com/github/dingdaoyi/controller/iot/RuleChainController.java:88-92` · security · **待复核**
  **建议**：加语句数/超时限制；调试接口限流并限管理员。

### 并发 / 数据正确性

- **H-17 · 轮询服务 `reloadAll()` 后线程池已 shutdown，轮询永久失效**
  `iot-server/src/main/java/com/github/dingdaoyi/driver/modbus/ModbusPollingService.java:52,73,85-90` + `iot-server/src/main/java/com/github/dingdaoyi/driver/opcua/OpcUaPollingService.java:56,77,89-94` · bug · **已验证**
  `scheduler` 是 `final` 字段，`stop()` 已 `shutdownNow()`，`reloadAll()` 随后 `start()` → 对已 shutdown 的 executor 调 `scheduleAtFixedRate` → `RejectedExecutionException`，该协议所有轮询不再恢复且不报错。
  **建议**：`scheduler` 改非 final 在 `start()` 重建；或 `reloadAll()` 只重建任务不 shutdown executor。

- **H-18 · Modbus 轮询建立 Socket 无连接超时**
  `iot-server/src/main/java/com/github/dingdaoyi/driver/modbus/ModbusPollingService.java:107-108` · bug/performance · **已验证**
  `new Socket(host, port)` 无 connect timeout（`setSoTimeout(3000)` 只管读），主机不可达时线程永久阻塞；轮询池只有 4 线程，4 台不可达设备即可让全部 Modbus 轮询停摆。每轮询新建 TCP 连接、无复用，大量设备下 TIME_WAIT/临时端口耗尽。
  **建议**：`socket.connect(addr, 3000)`；引入连接池或长连接复用。

- **H-19 · MQTT 上下线与连接注册用了 clientId，而取连接用 deviceKey → 通道永远取不到**
